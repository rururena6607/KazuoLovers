開発メンバー（ガブ、ひろし、とりはる）

- 最終発表は11月12日か19日のどちらか。早いほうの **11月12日に間に合わせ、11月11日に完成**させる

## 3. 負担の偏り（相談したいこと）

- **第1回はひろしが重い。** T-01 が遅れると全員の作業が止まるので、ひろしは T-01 を最優先にする。T-02・T-03 は T-01 のあとでよい
- **第2回は授業がなく、部の練習で試すまでの期間が短い。** ガブ（記録画面）とひろし（保存）の T-11〜T-16 がそろわないと試せないので、2人は第2回の前半に T-11・T-14 を終える
- **第2回はとりはるのタスクが少ない。** T-20（集計）を前倒しで進め、部の練習で記録をとる役もとりはるが中心になる案がある（未決定）
- **第3回はひろしが重い。** T-30・T-33 はどれも Edge Function。遅れたら T-25（Realtime）を第4回に回す
- **第4回に遅れたら、T-40（アタック記録）→ T-35（自動投稿）→ T-23（グラフ）の順に捨てる。** どれも推奨の機能で、発表の流れ（記録 → 分析 → AI コメント → LINE）には要らない
- 担当を変える場合は、実装計画書 2 節・3 節の所有範囲もあわせて直す

## 4. レビュー

PR のレビュアーは、実装者以外の1人とする（実装計画書 2.1）。

| 担当者 | レビューする PR |
| --- | --- |
| ガブ | ひろしの PR（データ・サーバ、管理画面、ログイン） |
| ひろし | とりはるの PR（計算・集計・分析画面） |
| とりはる | ガブの PR（記録画面、練習モード、PWA） |

`contracts`・要件定義書・実装計画書を変える PR は、3人全員がレビューする。
